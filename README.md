# 校园 GraphRAG：RAG模块

后端调用 `app.rag.retrieve(question, scope, request_id)`，获取原文证据、页码和可用图谱路径。不新增HTTP服务，不调用答案生成模型。

- [交接、初始化与迁移](docs/RAG_HANDOFF.md)
- [数据维护与AI接手](docs/AI_EXPANSION.md)
- `docs/logs/` 保存验证记录；`docs/design/` 保存原架构；`docs/ADR.md` 保存设计决策。

5份PDF共507页已整理为897个可回溯文本块，848块完成 `qwen3.7-text-embedding-flash` 1024维嵌入并发布。25块待复核OCR和24块目录保留在数据中，默认不参与检索。培养方案按专业、年级、培养类型隔离；已核验多跳图谱为CS2024子集，其余可直接检索原文，不编造图谱关系。

本机真实检索10例通过（8个混合检索来源正例、2个负例），另有10道多跳开发题回归。迁移向量在另一目录不调用API重建848条索引，结果哈希一致。这些是来源与路径验证，不是答案生成准确率或第二台电脑实测。

需要Python 3.11、Docker Neo4j及embedding API Key。交付 `dist/rag-ready-20261110.zip`，包含5PDF、离线处理结果和完整向量；在同学电脑安装依赖、填Key后运行初始化命令即可重建数据库，无需重做OCR或全文嵌入。切换模型/端点/维度须重新构建。密钥与密码只放本机 `.env.rag`。

原HTTP问答入口与独立RAG函数的返回契约不同，不能直接互换。原前端和答案生成流程仍保留，不属于此次运行要求。普通Git克隆不含被忽略的原PDF，应使用交付包或另拷原件。
