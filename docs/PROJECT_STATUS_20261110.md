### 两条调用链需要整合

网页现在调用：

```text
frontend → POST /qa/ask → pipeline.answer_question
         → 图检索 → facts → Ollama/模板 → QAResponse
```

最新独立模块调用：

```text
app.rag.retrieve → 已核验子图检索或全文原文检索 → RAGResult
```

两者返回契约不同：前者含 `answer/claims/citations`，后者含 `evidence/retrieval_type`，全文检索成功时可以没有图路径。应设计适配和证据约束，不能直接替换函数或将“找到原文”当成“多跳问题已有结论”。

证据：`backend/app/api/qa.py`、`backend/app/pipeline.py`、`backend/app/rag.py`、`backend/app/retrieval/documents.py`、`docs/RAG_HANDOFF.md`。

### 已验证的答案降级缺口

用真实 CS2024 知识包中的“通识教育课程”两条关系构造事实，直接运行现有模板：

- 原文包含：合计 66.5 学分，其中必修 51.5 学分、最低选修 15 学分。
- 模板输出：“计算机科学与技术2024级培养方案包含通识教育课程；通识教育课程引用了通识教育课程修读规定。”并附引用。

这说明模板具备关系与引用保留能力，尚缺按问题提取答案要点的能力。当前断言校验主要检查引用、路径覆盖和数字来源，也不能单独证明语义正确。

## 建议完成顺序

### 第一优先级：形成可验收的问答闭环

1. **统一问答入口和证据契约。** 将最新已核验检索能力接入网页问答，保留图路径、逐边原文及范围信息。专业/年份选择接入已有范围目录。证据不足、缺关系、范围冲突时明确追问或拒答。
2. **完成有实际答案的生成与降级。** 验证本地模型能从证据中回答学分、条件、上限等问题；修正只复述关系的模板。逐个检查答案与原文是否一致，而不只检查引用存在。
3. **确定无需付费 API 的基线。** 仓库已有本地 embedding 和 Ollama 实现，应配置并验证可用主路径；API 可保留为选配。使用本地 embedding 时须按该模型重建索引，不能混用现有 Flash 向量。
4. **补齐正式端到端评测。** 整理至少 10 道真实多跳题，覆盖 2/3 跳，给出标准路径、答案要点和来源；运行与线上一致的入口，输出逐题路径命中、答案正确性、失败原因，展示至少 3 项指标。另测缺范围、关系缺失、证据未核验、无来源、模型/向量服务故障。
5. **从干净目录复现部署。** 补齐 5 份原 PDF 或使用完整交付包；统一 Compose、依赖、模型缓存、初始化与知识包路径；清除对原开发机绝对路径的依赖。在隔离端口/项目名下验证，避免覆盖旧目录正在运行的服务。

验收方式应是一条可复现演示：提出真实问题 → 显示逐跳关系 → 返回明确答案 → 展开每条引用原文；移除关键关系或证据后，系统按预期拒答或降级，并记录失败阶段。
